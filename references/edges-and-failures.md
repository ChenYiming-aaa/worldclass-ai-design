# 研究局限与故障排查

全部故障诊断集中在本文件；各技术的执行细则见 SKILL.md 与对应 reference。

## 研究局限（不要过度解读）

- **SSoT 研究验证的是多样性，不是设计质量。** Sakana AI 的 String Seed of Thought 证明了随机字符串能提高特定生成任务的多样性；它**没有**验证网页设计的审美质量、可用性或复现率。
- **"候选更分散" ≠ "候选更好"。** 种子只保证你离开了默认中心，不保证你落在好的位置。筛选仍由人负责。
- **9/10 不是质量认证。** 它是流程内部的停止门槛，只在"同一 Critic prompt、同一基线"下具有相对可比性。不要对外宣称。
- **成本数据是案例数字，不是通用基准。** "Fable 占输出 token <10%"、"直接重做贵一倍"来自作者自己的案例。
- **9/10 门槛的稳定性依赖 Critic prompt 不变。** 换 prompt 等于换尺子，跨轮分数失去意义。

## 常见故障 → 诊断 → 处理

### 种子与候选（技术 1、2）

| 症状 | 诊断 | 处理 |
|---|---|---|
| 四个候选长得差不多 | 随机性来自模型内部，不是外部 | 检查是否真的用 shell 生成了种子；种子是否太短 |
| 种子用了但还是像 AI | 模型只看字符串表面（比如只取了首字符颜色） | prompt 中强调"超越表面找子模式、特殊数字、结构关系" |
| 候选够特别但很丑 | 正常。筛选是你的工作 | 用三步品味提取收敛；别指望种子自动产出好设计 |
| 大胆方向彻底失败 | 正常且有用 | 丢弃重来，**但保存 prompt**（新模型发布后再测） |

### 评审循环（技术 3）

| 症状 | 诊断 | 处理 |
|---|---|---|
| 评分忽高忽低 | Critic 标准太主观 | 升级到 "OK" 或 "Great" 档标准（见 `prompts.md` 技术 3） |
| 评分卡在 7–8 不动 | 骨架问题（左文右图 + 顶部导航）未解决，细节改不动 | 人介入，回到 Discover 换方向 |
| 循环不收敛，token 一直烧 | 未设停止条件 | 硬上限；连续两轮不升就停，由人调整 |
| 反馈含糊、无法执行 | Critic 未被要求给 tight & specific 反馈 | 在 Critic prompt 中显式要求，并要求指出具体位置 |
| 每轮建议自相矛盾 | Critic prompt 变了，或上下文被污染 | 固定 prompt；确认是全新上下文 |
| 输出开始照抄参考图 | 参考图被当作 target | 明确改成 baseline / moodboard 措辞 |
| 只顾细节不顾构图（或反之） | Critic prompt 只强调了一头 | 同时要求 high-level 与 fine details |

### 富媒体（技术 4、5）

| 症状 | 诊断 | 处理 |
|---|---|---|
| 页面有很多图但不知道为什么 | 图像是装饰不是材料 | 对每张图做删除测试；删掉不损失信息 = 删 |
| 视觉很炫但移动端崩了 | 富媒体未做降级 | 补静止替代帧、reduced-motion 分支、首屏性能预算 |
| 动效叠加后穿帮 | 折射/抠像未烘进页面背景色 | 先渲染在页面背景色上，再抠像 |
| 视频过渡有跳变 | 未用上一段末帧做下一段种子 | 用 final frame seed 下一段 |

### 交付（技术 6、7）

| 症状 | 诊断 | 处理 |
|---|---|---|
| 做完还是"一眼 AI" | 只做了 Discover/Define，没做 Deliver | 阶段 3 不可跳过；减法是关键 |
| 文案读起来很平均 | 模型顺手写的 | 人工重写 H1、主按钮、空状态、错误态 |
